1. git pull
-----------
What it does:
◼ Fetches changes from the remote and automatically merges them into your current local branch.

Equivalent to running:
~]$ git fetch && git merge origin/branch-name

When to use:
◼ When you want to directly update your local branch with the latest remote changes.
◼ When you trust the remote changes and don’t need to review them first.

Command:
~]$ git pull origin main
(Fetches main from origin and merges it into your current branch.)

Effect:
◼ Your local branch is updated with the remote changes.
◼ May result in merge conflicts if your local changes clash with remote changes.



2. git fetch
------------
What it does:
◼ Downloads the latest changes (commits, branches, tags) from the remote repository but does not merge them into your local branches.
◼ Updates your remote-tracking branches (e.g., origin/main) but leaves your local branches (e.g., main) unchanged.

When to use:
◼ When you want to check what changes are available in the remote before merging them.
◼ When you need to review changes before applying them.

Command:
~]$ git fetch origin
(Fetches updates from the origin remote.)

Effect:
◼ Your local repo now knows about remote changes, but your working directory remains unchanged.
◼ You can inspect changes using:
~]$ git log origin/main  # See what's new in the remote branch
~]$ git diff main origin/main  # Compare local and remote





Which One Should You Use?
🖥 Use git pull when:
✔ You’re sure the remote changes won’t conflict with yours.
✔ You want a quick update without manual merging.

🖥 Use git fetch when:
✔ You want to see what’s changed before merging.
✔ You’re working on a shared branch and need to avoid surprises.
