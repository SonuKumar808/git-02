1. git pull
-----------
What it does:
◼ Fetches changes from the remote and automatically merges them into your current local branch.

Equivalent to running:
~]$ git fetch && git merge origin/branch-name

When to use:
◼ When you want to directly update your local branch with the latest remote changes.
◼ When you trust the remote changes and don’t need to review them first.

Command:
~]$ git pull origin main
(Fetches main from origin and merges it into your current branch.)

Effect:
◼ Your local branch is updated with the remote changes.
◼ May result in merge conflicts if your local changes clash with remote changes.



2. git fetch
------------
What it does:
◼ Downloads the latest changes (commits, branches, tags) from the remote repository but does not merge them into your local branches.
◼ Updates your remote-tracking branches (e.g., origin/main) but leaves your local branches (e.g., main) unchanged.

When to use:
◼ When you want to check what changes are available in the remote before merging them.
◼ When you need to review changes before applying them.

Command:
~]$ git fetch origin
(Fetches updates from the origin remote.)

Effect:
◼ Your local repo now knows about remote changes, but your working directory remains unchanged.
◼ You can inspect changes using:
~]$ git log origin/main  # See what's new in the remote branch
~]$ git diff main origin/main  # Compare local and remote


Which One Should You Use?
🖥 Use git pull when:
✔ You’re sure the remote changes won’t conflict with yours.
✔ You want a quick update without manual merging.

🖥 Use git fetch when:
✔ You want to see what’s changed before merging.
✔ You’re working on a shared branch and need to avoid surprises.

Git Commands:
=============

1. git init
-----------
◼ Purpose: Initialize a new git repository in the current directory
◼ Usage: we run this command in a project folder to convert it into a git repository. It creates a .git directory where git stores all its configuration files and version history.
◼ Ex: git init


2. git status
-------------
◼ Purpose: Shows the current status of the working directory and staging area.
◼ Usage: This command is used to check whether there are any modified, added, or deleted files in the working directory that need to be staged or committed.
◼ Ex: git status


3. git add
----------
◼ Purpose: Add files or changes to the staging area (index) in the preparation for a commit.
◼ Usage: You specify the files to add or use a wildcard (e.g., git add . to add all files).
◼ Ex: git add test.txt


4. git commit
-------------
◼ Purpose: Commits the staged files to the local repository, saving your changes along with a commit message.
◼ Usage: This records your staged changes and adds them the local repository's history.
◼ Ex: git commit -m "commit message describing changes"


5. git push
-----------
◼ Purpose: Pushes the committed changes from local repository to the central repository (remote repo like Github).
◼ Usage: After commiting locally, use this to share your changes with others by sending them to the central repository.


6. git restore
--------------
◼ Purpose: Used to undo changes in the working directory and the staging area.
◼ Usage: If a file is unstaged, git restore will discard local changes made to that file.
◼ Ex: git restore test.txt --> Unstage a staged file (without discarding changes)
      git restore --staged test.txt


7. git log
----------
◼ Purpose: Displays the commit history, including commit Id's, author information, dates and commit message.
◼ Usage: This is useful to view the history of changes made to the project.
◼ Ex: 
   git log 
--> to view a simpler summary, you can add options:
   git log --oneline


8. git rm
---------
◼ Purpose: Removes a file from both the working directory and the staging area, and it schedules the deletion for the next commit.
◼ Usage: If you want to delete a file, this command removes it and stages the change for the commit.
◼ Ex:
    git rm file_name.txt
    git commit -m "removed test.txt"
    git push origin main


9. git clone
------------
◼ Purpose: Downloads a copy of an existing git repository (usually from a remote central repository) to your local system.
◼ Usage: This command is typically used when you want to start working on an existing project and need a copy of the central repository on your machine.
◼ Ex:
git clone https://github.com/username/repository.git
